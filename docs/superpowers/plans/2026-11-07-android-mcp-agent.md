# Android MCP Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a locally running Android conversational agent that uses remote inference and HTTP MCP tools, preserves separate conversations, reads selectable-text PDFs, and creates shareable Markdown files.

**Architecture:** Keep Flutter presentation above an app-owned backend interface. A single Rust coordinator owns persistence, permissions, context, inference, and sequential tool execution; an Android foreground-service adapter keeps user-initiated runs alive independently of the Activity. SQLite holds durable state, app-private files hold attachments/artifacts, and Android-backed secure storage holds configured credentials.

**Tech Stack:** Existing Flutter/Dart, Rust 2021, flutter_rust_bridge 2.13.0, Android Kotlin runner; proposed additions are rusqlite with bundled SQLite, serde/serde_json, reqwest with rustls and streaming, tokio for concrete async transport/cancellation seams, futures-util, thiserror, uuid, sha2, and a lopdf PDF adapter confined to a disposable Android `:pdf_worker` process with bounded parent-side IPC. Confirm versions/features/licenses/Android support in Task 1; these dependencies are not present or installed by this plan. Use tempfile in tests. Native Android adapters supply Keystore encryption, Storage Access Framework, notifications, and content-URI sharing without general filesystem permissions.

**Spec:** [Android MCP chat agent v1 design](../specs/2026-11-07-android-mcp-agent-design.md). Read it and repository `AGENTS.md` before each task. The user later authorized subagent-driven execution; Task 1's emulator feasibility gate passed. The approved separate-process PDF approach is specified in the [PDF worker amendment](../specs/2026-11-07-pdf-worker-design.md); its detailed contract was approved when the user asked to continue; Task 2 resumes under that contract.

## Global Constraints

- Android only initially; no remote agent host, local inference engine, OCR, visual PDF interpretation, OAuth, code execution, sync, voice, or scheduled jobs.
- Rust edition stays 2021; flutter_rust_bridge stays 2.13.0. No unrelated upgrades, vendored Cargokit edits, lint weakening, or hand-edited generated bindings.
- One executing run application-wide, sequential calls, many conversations and persisted approval waits. Waiting releases the execution slot.
- New tools default to ask. Rules are profile/server/exact-tool scoped; dispatch rechecks live policy and exact immutable approved arguments. Server/schema changes revoke automatic-allow trust.
- Profile configuration snapshots are conversation-owned; explicit apply-updated-profile changes future turns. Live permission revocation still affects old conversations.
- OpenAI-compatible Chat Completions with structured tool calls; Streamable HTTP MCP. Native provider APIs, legacy SSE MCP, stdio, resources/prompts, and server-initiated sampling are not v1 requirements.
- Never automatically replay tool requests. Uncertain dispatch stays outcome unknown, including when the run is cancelled or interrupted. Stop is local/best-effort, not remote rollback.
- Initial budgets: 20 inference requests, 40 tool attempts, 15 minutes cumulative active time; 30-second connect and 120-second response-idle timeout, bounded by the run deadline. Approval waits do not spend active time.
- PDF: 10 MiB/file, 500 pages/file, 2 MiB extracted UTF-8 text/file, 5 attachments/conversation. Parse only in disposable `:pdf_worker`; 60-second request deadline, 64 KiB frames, 8 KiB text chunks, 16 MiB cumulative wire cap, five-second cleanup grace, one active extraction. Same UID provides fault containment, not permission isolation or a hard total RAM ceiling. Reads return at most 32 KiB. MCP raw result cap is 1 MiB. Generated UTF-8 output cap is 1 MiB/file.
- Model context window is explicit configuration; estimates are labeled estimates. Never silently discard selected content or pretend a partial read covered a whole PDF.
- Secure credentials stay outside SQLite/prompts/exports. TLS validation remains enabled. HTTP requires per-endpoint opt-in; never forward credentials across origins.
- User data stays in app-private storage except explicit inference/tool transmission or user export. Exclude private data from automatic backup. No payload telemetry.
- Headless tests use fake clocks/transports, temporary storage, and fixed fixtures; no real services, credentials, sleeps, or shared state. Device behavior needs device evidence.
- No branch, commit, push, CI modification, publication, or release-signing change is authorized by requesting this plan. If execution later authorizes commits, stage only each task's files at its review checkpoint.

## Review Focus

1. Schema or endpoint replacement while approval is pending must invalidate execution; Task 4 tests the race at dispatch.
2. A server applies a write but its response is lost or oversized; Task 7 must preserve uncertainty/outcome and never retry it.
3. Stream bytes split inside UTF-8, SSE frames, or tool JSON must never dispatch incomplete arguments; Tasks 5–6 test fragmentation and malformed completion.
4. A compressed/malformed PDF crashes or overworks its parser; Tasks 2 and 10 keep decoding outside chat, bound host IPC/output, terminate the active worker on deadline/cancellation, and never publish a truncated result as complete. Test failed termination explicitly; do not equate this with a total-memory guarantee.
5. Activity recreation, denied notifications, or a pending approval must not create a second run or accidentally approve a stale call; Tasks 1 and 12 test ownership and notification routing.

## Shared contracts

Task 3 defines these names before downstream tasks consume them. Opaque ID newtypes wrap UUIDs: `ConversationId`, `ProfileId`, `EndpointId`, `ServerId`, `RunId`, `AttemptId`, `AttachmentId`, `ArtifactId`, `CredentialRef`; serialize without secrets. `AppResult<T> = Result<T, AppError>`.

Records:
- `EndpointConfig { id, name, base_url, model, context_tokens: u32, max_output_tokens: u32, temperature: f32, allow_http: bool, credential: Option<CredentialRef> }`.
- `ServerConfig { id, name, url, allow_http: bool, secret_headers: Vec<(String, CredentialRef)> }`.
- `Profile { id, name, endpoint_id, server_ids, instructions, limits: RunLimits }`; `ProfileSnapshot` resolves configuration values and references, never secret values, plus a revision.
- `RunLimits { max_inference_requests: u32, max_tool_attempts: u32, active_timeout_ms: u64 }` defaults to 20, 40, 900000. `SafetyLimits` holds fixed byte/page caps above.
- `ToolKey { profile_id, server: ToolServer, name }`, where `ToolServer` is configured MCP identity or `LocalFiles`; `ToolDefinition { key, schema_json, schema_digest, destination_digest }`.
- `ToolCall { key, provider_call_id, arguments_json }`; `ApprovalBinding { attempt_id, definition_digest, arguments_digest }`; `PermissionRule::{Ask, Allow, Block}`.
- `RunState::{Running, WaitingApproval, Paused, Completed, Cancelled, Failed, Interrupted}`; `AttemptState::{Proposed, Denied, Approved, Dispatching, Succeeded, Failed, OutcomeUnknown}`.
- `Message { id, conversation_id, run_id: Option<RunId>, role, text, partial: bool }`; `ToolOutcome` preserves protocol error versus remote success versus unknown status independently of result payload availability.
- `PageText { physical_page: u32, text, status }`, `AttachmentSummary`, `ArtifactSummary`, `ConversationSnapshot`, `AppSnapshot`, and `AppEvent { sequence: u64, conversation_id: Option<ConversationId>, kind }` expose only public state. Storage persists event ordering; UI can refresh a full snapshot after an event gap.

Platform seam: `CredentialProvider::resolve<'a>(&'a self, reference: &'a CredentialRef) -> Pin<Box<dyn Future<Output = AppResult<SecretValue>> + Send + 'a>>` supplies redacted-on-Debug values just in time without blocking a Dart/platform callback; `SecretValue` is never serializable. `RunClock::active_elapsed_ms(&self) -> u64` and transport seams are injected for tests. Concrete production threading comes from Tasks 1/7, not from synchronous widget callbacks.

Commands crossing FRB use tagged `AppCommand` DTOs (no arbitrary eval): configure endpoint/server/profile, snapshot conversation, apply profile, set rule, start turn, approve/deny, cancel/resume, history CRUD/export, attachment/artifact operations, and inference-disclosure acknowledgment. Declare each variant's typed payload in the task that owns its behavior. `CommandReply` is a tagged typed result; callers do not parse error strings to infer state.
