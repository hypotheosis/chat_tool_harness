# Android runtime feasibility — Task 1 correction

One `FlutterEngine` is created/cached as `agent_runtime` in `AgentApplication`, and `MainActivity` supplies it without destroying it on detach. Eager engine/Dart initialization does **not** start a foreground service. The Dart `startRunService` method is an explicit entry point; the native adapter rejects it unless an Activity is resumed, and acknowledges success only when `AgentService.onStartCommand` has called `startForeground` and marked the runtime running. This is a visible-app guard, not proof of a user gesture: the future coordinator/UI must invoke it from an explicit user action. There is no boot receiver, implicit service start, permanent daemon, or Rust coordinator yet. A rejected synchronous start or failed foreground promotion pauses and surfaces `SERVICE_REFUSED`; no automatic retry. Lifecycle commands are queued until an EventChannel listener connects, then drained once. This in-process queue is not process-death persistence.

The debug-only Android probe registers `Application.ActivityLifecycleCallbacks`, finishes the actual Activity, and executes a gated step via the live service after the Activity destruction callback when the count is zero. It launches/restores `MainActivity`, verifies the same runtime ID and active service, and dispatches the actual notification Stop `PendingIntent`. The retained Dart isolate's existing FRB `greet` is called after the detached service step, showing that the bridge remains callable; the Dart test invocation itself is not a service-owned Rust coordinator step. A later listener observes `interrupted` after a debug probe directly invokes the real `AgentService.onTimeout` callback. This tests callback handling, **not** an OS-enforced timeout. The debug probe and its counters are absent from the release variant. The release APK was built, but APK inspection of its packaged classes was not performed.

`dataSync` with `FOREGROUND_SERVICE` and `FOREGROUND_SERVICE_DATA_SYNC` is chosen for bounded user-started inference/MCP transfers, not unrestricted perpetual compute. On Android 15+, dataSync has a six-hour/24-hour system limit and `onTimeout`; the separate 15-minute app budget is for the later coordinator. Android 14+ requires the declared type and permission. Android 13+ `POST_NOTIFICATIONS` denial does not inherently prohibit an FGS; runtime `notificationVisibility` reads `NotificationManager.areNotificationsEnabled()` rather than a fixture flag. Actual denied-permission behavior and real OS service refusal/timeout have **not** been established here. Notification carries generic content and a Stop action. See [Android service types](https://developer.android.com/develop/background-work/services/fgs/service-types), [timeouts](https://developer.android.com/develop/background-work/services/fgs/timeout), and [launch restrictions](https://developer.android.com/develop/background-work/services/fgs/launch).

Build configuration uses Flutter defaults: minSdk 24, targetSdk 36, compileSdk 36. Tested on Android 16/API 36 x86_64 emulator-5554 with Flutter 3.41.7, Dart 3.11.5, Gradle 8.14 and JDK17 for Gradle. Debug APK produced armv7/aarch64/x86_64/i686 Rust artifacts; release APK produced armv7/aarch64/x86_64. No package is a release-signing/distribution claim. Physical-phone switching/OEM battery behavior and process-death recovery remain untested.

Dependency decision record (no new dependency is justified in Task 1): current Flutter embedding plus FRB `=2.13.0` provide the Android engine/bridge; adding a network/database/PDF crate before its owning task would not validate its transport, schema, ABI, or license. Research candidates as of this correction: [`rusqlite 0.41.1`](https://docs.rs/crate/rusqlite/0.41.1) with `bundled` for consistent Android SQLite builds (later: NDK ABI compile, encryption/backup policy and transitive-license check); [`reqwest 0.13.5`](https://docs.rs/crate/reqwest/0.13.5) with `json` and default rustls rather than native OpenSSL (later: Android TLS trust, streaming/idle timeout, redirect/credentials tests); [`tokio 1.54.1`](https://docs.rs/crate/tokio/1.54.1) with only needed `rt-multi-thread`, `time`, `sync`, `net` features if the concrete reqwest transport seam requires an app-owned executor (later: cancellation/shutdown and Android runtime tests); [`serde 1.0.229`](https://docs.rs/crate/serde/1.0.229) with `derive` for typed protocol/config boundaries (later: schema compatibility and validation); [`lopdf 0.47.0`](https://docs.rs/crate/lopdf/0.47.0) for text extraction only (later: PDF limits, malformed-input/fuzz tests and Android ABI/license checks). These are **research versions/features, not selected/validated dependencies**; lock them deliberately in `rust/Cargo.lock` once their owner task proves compatibility and audits license/transitive packages. The current Cargo lockfile remains unchanged by this correction.
